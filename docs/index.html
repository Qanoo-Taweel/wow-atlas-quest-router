      Itinerary

        The algorithm

        How ATLAS routes your quests

        ATLAS was published for covering every edge of a graph at low cost (test generation for finite state machines, then large-scale arc routing). Quest routing is an arc-routing problem: every quest step is a required edge (a self-loop at its location), every road, flight and boat is an ordinary edge with a travel time.

        1

        Local DAG

        From the last edge of the tour, an iterative depth-first search (explicit stack) lists every reachable edge. Its reverse post-order is a topological order; edges that point backwards close cycles and are left out for this iteration only.

        paper §3.1, §3.2
        2

        Longest path DP

        Walking the DAG in order, each edge inherits the best value of its predecessors: utility grows by one unit for every available quest step, cost grows by the travel time.

        Path_Score = utility − λ·cost
        3

        Pick the chain

        The best end edge is the argmax of the path score, with the paper's six-term edge score (required, connectivity, efficiency, savings, regret, proximity) as tie-breaker.

        Algorithm 1, line 15 · eq. (1)
        4

        Extend and repeat

        Backtrack comeFrom, append the chain to the tour, mark the quest steps served (which unlocks the next step of each quest), lazily reset the arrays and go again until nothing is left.

        O(|R| · (|V| + |E|))

        Edge score (Kabaca, Samir & Takan, eq. 1)

        score(e) = 1e∈R·1000 + (deg⁺+deg⁻)·0.5 + value/weight·10 + SCW(e)·50 + R(e)·100 + P(e)·20

        Implemented as a Composite of six Strategy objects (Atlas/ScoreComponents.lua), with the paper's adaptive weights for sparse versus dense graphs.

        What the addon adds for a game world

        • Precedence: accept → objectives → turn in, and quest chains.
        • Weights in seconds and a cost penalty λ, so a chain never takes a silly detour.
        • Multi-DAG sampling: 4 DFS orderings per iteration, ATLAS keeps the best chain.
        • One-use edges: the hearthstone closes after its first use.
        • One iteration per frame in a coroutine, so the game never freezes.

        Faithful to the original

        Atlas/AtlasClassic.lua is a line-by-line port of savastakan/atlas Atlas.java (including Java's HashSet iteration order). On 7 finite state machines, from the 6-state bbtas benchmark to a 1,000-edge machine, it prints exactly the same test sequence as the Java program. The weighted planner, the website and the addon share the same code path and are checked route for route.

        Get it

        Install and use in game

        1. Download the repository (Code → Download ZIP) and unzip it.
        2. Copy the folder AtlasQuestRouter into World of Warcraft/_classic_era_/Interface/AddOns/ (the Forever client folder).
        3. Check the version: in game type /dump select(4, GetBuildInfo()). If it differs from 11507, put that number on the ## Interface: line of AtlasQuestRouter.toc.
        4. Enable “Atlas Quest Router” in the AddOns menu on the character screen.
        5. Type /aqr import (or /aqr demo) and then /aqr plan.

        Slash commands

        /aqr help              all commands
/aqr import            track known quests from your log
/aqr add <id|name>     track one quest
/aqr remove <id>       stop tracking
/aqr list | clear
/aqr plan              ATLAS route from where you stand
/aqr next              current leg done, show the next
/aqr show | hide       tracker window
/aqr from <place>      plan from somewhere else
/aqr speed foot|60|100 ground speed
/aqr hearth <place>    where your hearthstone is set
/aqr demo              sample quests for your faction
